# 训练任务草稿保存与启动就绪引导设计

状态：已实施，并于 2026-08-20 完成双分辨率 Chrome 验收和独立 UI/UX 复核。

```text
UI/UX REVIEW PASSED
```

## 1. 问题与目标

新建训练任务页面当前使用同一个 `valid` 状态控制“保存草稿”和“保存并启动”。该状态同时要求任务身份字段、模型名称和全部模型训练资源完整，导致未完成资源配置的任务不能保存为草稿。

页面只显示禁用按钮，没有明确指出具体缺失字段。用户即使已填写大量内容，也无法判断是任务 code、模型名称，还是某个模型最终解析后的数据集、超参模板或 BaseModel 不完整。

本次目标：

- 允许保存尚未完成资源配置的草稿；
- 仅在启动前要求每个模型具备有效训练数据集、超参模板和 BaseModel；
- 任务总体设置继续作为可选默认值，不成为独立必填区；
- 使用就地必填标识和缺失原因指导填写，不增加顶部汇总卡。

## 2. 已确认的现有语义

每个模型的最终资源通过模型设置与任务默认值共同解析：

- 模型选择“继承任务默认”时使用任务总体设置；
- 模型显式选择资源时覆盖对应任务默认值；
- 数据集、超参模板和 BaseModel 可以分别来自不同层级；
- 多数据集只有在映射包含至少一个数据集和至少一个目标类别时才视为有效。

后端草稿创建和更新已经允许资源字段为空；启动服务会重新解析并严格校验资源。因此本次不修改数据库、迁移或 API 合约。

## 3. 提交状态

### 3.1 草稿可保存

`draftValid` 同时满足：

- 任务名称非空；
- 任务 code 符合 `^[a-z][a-z0-9-]{2,31}$`，且当前未确认冲突；
- 模型数量为 1–10，并符合训练模式已有数量约束；
- 每个模型名称非空。

草稿保存不要求任务默认资源或模型训练资源完整，也不依赖当前主机训练能力。
单模型模式必须恰好一个模型；单算力串行模式至少两个模型；自定义序列至少一个模型。模式数量不满足时，在训练模式控件下显示具体提示。

### 3.2 可以启动

`launchReady` 同时满足：

- `draftValid` 为真；
- 每个模型最终解析后具有有效训练数据集；
- 每个模型最终解析后具有有效超参模板；
- 每个模型最终解析后具有有效 BaseModel；
- 当前主机训练能力可用。

“保存并启动”继续先保存草稿，再调用启动接口。服务端启动校验是最终一致性与并发变化的安全边界。

## 4. 页面引导

采用“仅就地提示”，不增加页面顶部完成度或错误汇总卡。

### 4.1 草稿必填字段

以下标签显示红色 `*`：

- 训练任务名称；
- 任务 code；
- 模型名称。

缺失或格式错误时，在对应控件下显示具体原因。任务 code 保留格式、冲突和可用状态提示。

### 4.2 启动必填资源

每个模型的以下字段显示红色 `*` 和“启动必填”说明：

- 训练数据集；
- 超参模板；
- BaseModel。

资源从任务默认值成功继承时，模型设置区明确显示“已继承：资源名称”。任务默认值为空且模型没有显式选择时，字段下显示：

> 未配置：请在任务总体设置中提供默认值，或在当前模型中选择。

多数据集映射不完整时使用专门提示：

> 映射未完成：至少选择一个数据集并保留一个目标类别。

提示必须同时依赖文字与错误边框，不仅使用颜色表达状态。所有文字不低于 13px。

### 4.3 按钮反馈

- “保存草稿”只由 `draftValid` 和保存中状态控制；
- “保存并启动”由 `launchReady`、训练能力和保存中状态控制；
- 禁用按钮保留说明首个未满足条件的 `title`；
- 字段附近同时呈现所有缺失资源，使用户不必通过反复悬浮按钮逐项排查。

## 5. 实现边界

- 将页面当前 `valid` 拆分为 `draftValid` 与 `launchReady`；
- 继续复用 `effectiveResourceIds()` 解析资源来源；
- 在 `trainingResources.ts` 增加最小的缺失资源计算函数，按钮状态与模型字段提示使用同一结果；
- “添加模型”只受训练模式、1–10 数量上限和保存中状态约束，不再要求已有模型先完成资源配置；
- `save(false)` 使用 `draftValid`，`save(true)` 使用 `launchReady`；
- 不新增依赖，不建立新的表单状态框架，不修改后端草稿与启动语义。

## 6. 错误和状态变化

- 任务默认值、模型资源模式或显式选择变化后，缺失提示立即重新计算；
- 继承资源被删除、失效或资源列表刷新后，模型自动回到缺失状态；
- 启动按钮与服务端结果不一致时，以服务端错误为准，并继续使用现有错误消息；
- 主机训练能力不可用时仍可保存草稿，启动按钮保持禁用并显示能力原因。

## 7. 验证

自动化测试覆盖：

- 资源全部继承、全部显式配置和三项混合来源；
- 缺少单数据集、多数据集映射、模板或 BaseModel；
- 资源不完整时可以保存草稿但不能启动；
- 任务身份字段或模型名称缺失时两个提交动作均不可用；
- 训练能力不可用时可以保存草稿但不能启动。
