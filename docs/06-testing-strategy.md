状态：pytest、Vitest、生产构建，以及隔离的视频导入和采样帧真实链路冒烟已启用；手动/自动标注已具备单元、组件和 API/Worker 集成测试，真实模型与导出端到端仍待补充。

## 遗留测试基线

`dataset-manager-1` 的前后端包清单没有正式测试脚本。仓库中存在 yt-dlp、缩略图和抽帧格式的临时脚本以及历史测试输出，但不能证明当前提交的正确性。

## 测试层级

### 单元测试

优先覆盖无 I/O 业务规则：

- 视频状态的合法和非法转移。
- 三种采样模式、边界时长、FPS 和参数限制。
- train/val 视频级划分与目标比例偏差。
- 帧启停、分组与导出资格推导。
- 路径解析、ID 和配置校验。
- multi/single 运行模式、注册审批和项目角色权限。
- 项目标签名称、中文描述、颜色校验、排序、启停、版本冲突和项目内唯一性。
- GPU 命令、PyTorch CUDA、ONNX CUDA Provider、Ultralytics 与 Transformers 依赖探测的成功和降级路径。
- 标注草稿历史、矩形边界、视图坐标变换、追加/覆盖合并和冲突判断。

### 数据与迁移测试

- 在空数据库上执行全部迁移。
- 从每个受支持的前一版本升级。
- 对真实 schema 的脱敏样本执行遗留项目导入预览。
- 验证外键、唯一约束、任务领取竞争和租约过期。
- 验证单项目第 999 条视频成功、第 1000 条由数据库拒绝，且其他项目不受影响。
- 验证项目标签外键、项目内名称唯一、项目删除级联、中文描述迁移回填和已引用标签拒删。
- 验证标注删帧级联、标签删除受限、帧修订号，以及推理模型和新增任务类型迁移。
- 迁移失败必须回滚或留下可诊断状态。

### API 集成测试

- 项目、视频、帧、标注、模型、自动标注、导出和任务的正常路径。
- 标签 owner/editor 写、viewer 只读、非成员 404，以及已认证能力接口。
- 参数错误、资源不存在、冲突、权限不足和部分失败。
- 分页、过滤、排序、幂等键和乐观并发。
- 文件下载的 Range、路径安全与内容类型。
- 事件断线重连后能从任务资源恢复最终状态。

### Worker 与媒体集成测试

- 用短小、仓库可生成的测试视频验证 ffprobe 和 FFmpeg。
- yt-dlp 网络行为默认使用假适配器；少量真实网络冒烟测试单独运行，不作为普通单元测试前提。
- 验证任务成功、超时、进程终止、重试、取消和重复领取。
- 验证 FFmpeg stdout/stderr 持续消费、线程限制和结构化进度。
- 验证临时输出发布、磁盘写失败和数据库提交失败后的清理/补偿。
- 验证模型文件/目录入库、符号链接拒绝、单张假推理映射，以及批量逐帧提交、取消和部分成功保留。

### 前端测试

- 组件测试覆盖表单、状态、错误、空数据和权限差异。
- API 客户端使用契约样本测试序列化和错误映射。
- 端到端测试覆盖创建项目到导出数据集的主路径。
- 批量操作测试请求数量，防止恢复逐帧请求瀑布。
- 关键工作区做键盘操作和基础可访问性检查。
- 批量抽帧执行期间验证页面仍可操作，进度只更新相关行和任务抽屉。
- 验证视频列表 25/50/100/200/全部分页、当前页全选/半选、999 容量禁用和 viewer 只读启停状态。
- 验证状态信息优先级覆盖活动任务、新失败/取消、停用、筛帧、恢复全部、已采样、待抽帧和基础媒体状态。
- 验证停用视频仍可播放、配置采样、抽帧和管理帧；未来下游功能另测 `enabled=true` 过滤。
- `AppShell.spec.ts` 覆盖全局导航、权限入口、侧栏偏好、最近项目上限、固定图标轨道和浮层账号菜单命令。
- `ProjectLabelsView.spec.ts` 覆盖双语紧凑新增、0 起始顺序、启停、原子排序、viewer 只读、候选颜色会话恢复及成功/失败后的换色规则；`labelColor.spec.ts` 覆盖高饱和随机颜色和已有色相避让；`AppShell.spec.ts` 另覆盖 GPU 降级提示每浏览器会话只显示一次。
- `ProjectLayout.spec.ts` 覆盖项目加载、紧凑上下文栏和真实路由页签；内外两层路由过渡不得重建整个项目外壳。
- `TaskCenterDrawer.spec.ts` 使用 fake timer 覆盖终态未读判断、已读清除、项目级重试、interval 清理和 append-to-body 浮层渲染。
- 使用 Element Plus `append-to-body` 的组件测试必须从 `document.body` 查询浮层内容，并在用例结束后清理；不得为了测试便利退回会受局部 overflow 影响的内联浮层。
- `base.spec.ts` 锁定 Element Plus 全局过渡时长、页面进入位移和 `prefers-reduced-motion` 降级，防止全局样式覆盖再次削弱组件动效。
- 组件测试验证尺寸令牌和固定轨道的结构约束；字体观感、动效节奏、浮层定位及 100% 浏览器缩放下的页面一致性仍需浏览器目测，当前没有像素级视觉回归测试。
- `recentProjects.spec.ts` 覆盖损坏的 localStorage、去重、当前项目优先和 5 项上限。
- 标注组件测试覆盖焦点路由、viewer 禁用入口、Konva 绘制/选择/变换、缩放平移、撤销/重做、快捷键输入保护、切帧/关闭保存、对象列表和缩略图导航。
- 自动标注组件测试覆盖模型登记、自由英文类别与 `All`、单张草稿、追加/覆盖参数、批量只读状态和任务轮询。

## 必测工作流

1. 创建项目并导入本地视频。
2. 远程视频下载失败后重试成功。
3. 计算采样、抽帧、重启服务并恢复任务结果。
4. 筛选部分帧、分组并导出 train/val。
5. 两个客户端并发修改同一资源时检测冲突。
6. 路径逃逸、越权访问和跨项目任务订阅被拒绝。
7. 手动标注、直接模型自动标注、人工复核和冲突报告。
8. Docker 未声明 GPU 时正常启动并显示功能降级。
9. 停机复制工作区后在 Linux 或 Windows 重新定位并启动。

图片数据集和数据集导出测试在对应功能进入实现范围时补充；真实 GPU 模型文件、长视频批量性能和浏览器视觉回归仍需单独冒烟。

## Fixtures

- 媒体 fixture 应尽量用测试过程生成，体积小且许可明确。
- 数据库 fixture 通过迁移或工厂创建，不长期保存来源不明的二进制数据库。
- 遗留兼容 fixture 放在专门测试资源中并脱敏，不直接依赖 `.ai-local/references/`。
- 测试目录必须隔离，完成后只删除由该测试显式创建的路径。

## 质量门槛

- 每个缺陷修复先有可复现测试。
- 新状态转移、迁移和权限规则必须有正反例。
- 覆盖率数字不是唯一门槛；核心领域分支和失败路径必须显式枚举。
- 合并前至少运行格式、静态检查、单元、集成和前端构建。

后端使用 pytest，前端单元/组件使用 Vitest。当前可执行命令：

```bash

cd backend && uv run ruff check src tests alembic
cd frontend && npm test
```
