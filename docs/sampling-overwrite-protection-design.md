# 采样覆盖保护与视频业务状态设计

状态：已确认，待实施。

## 目标

- 防止重复配置采样或重新抽帧意外删除当前采样帧、标注和筛帧结果。
- 保留必要的重新抽帧能力，不恢复老版不可逆的视频状态流转。
- 在单视频和批量操作中使用相同的风险判断，并由后端实施最终保护。
- 恢复可快速识别的“业务状态”展示，但不新增容易漂移的持久化状态枚举。

不保存历史帧快照，也不提供重抽帧后的回滚。重新抽帧成功后仍由当前原子发布流程替换上一代帧；失败或取消继续保留上一代帧。

## 事实来源与风险分类

风险判断只读取结构化数据：

- `sampling is null`：未配置采样方案。
- `sampling is not null && extracted_frames == 0`：已配置、未抽帧。
- `extracted_frames > 0`：已完成抽帧。
- `version != applied_version && extracted_frames > 0`：已有帧仍属于旧方案，当前方案等待重新抽帧。
- `frame_revision > 1`：当前一代帧保存过筛帧变更，即使后来恢复为全部启用也仍视为变更过。
- 当前视频存在至少一条 `FrameAnnotation`：已有标注。

重新抽帧分为三级风险：

| 级别 | 条件 | 所需确认 |
|---|---|---|
| `none` | 尚未抽帧 | 不提示覆盖 |
| `light` | 已抽帧，且没有标注、`frame_revision == 1` | 普通覆盖确认 |
| `destructive` | 已有标注或 `frame_revision > 1` 任意一项成立 | 红色强警告，确认按钮倒计时 3 秒 |

风险由服务端在创建任务的事务中重新计算。前端提交的风险级别低于实时级别时，该视频进入批量响应的 `rejected`，不会创建任务；前端刷新数据并要求用户按最新风险重新确认。

视频列表只需要知道某视频是否存在标注，不计算全部标注框数量。后端通过当前页视频 ID 做一次带索引的关联查询，返回 `has_annotations`，避免逐视频请求和持续维护冗余计数字段。

## 单视频采样配置

首次配置时保持现有表单和“保存方案”按钮。

再次打开已经配置但尚未抽帧的视频：

- 表单载入并显示当前方案。
- 显示“已配置采样方案，再次保存将覆盖当前方案”。
- 表单允许直接编辑，主按钮显示“覆盖保存”。

打开已有采样帧的视频：

- 显示“当前视频已按现有方案完成抽帧；修改方案不会立即替换当前帧，需要再次执行抽帧才会生效”。
- 表单和主按钮默认禁用。
- 表单上方提供“强制修改采样方案”开关；开启后允许编辑，主按钮显示“覆盖保存”。
- 已经修改方案但尚未重新抽帧时，仍按已有采样帧处理并默认锁定。

配置接口默认只接受首次配置。请求显式携带以下覆盖级别：

- `none`：拒绝任何已有方案。
- `configured`：只允许覆盖尚未抽帧的已有方案。
- `sampled`：允许覆盖已有采样帧视频的方案。

服务端逐项重新判断，不能用前端开关替代权限和状态检查。

## 单视频重新抽帧

未抽帧视频直接创建任务。已有帧视频点击“抽帧”后先确认：

- `light`：说明当前采样帧会被替换，但当前没有已保存标注或筛帧变更。
- `destructive`：列出“已有标注”和“保存过筛帧变更”中实际命中的风险，明确当前帧、标注及帧启停状态会被永久替换；确认按钮 3 秒后可用。

抽帧接口接收 `overwrite_level: none | light | destructive`。服务端实时风险高于请求级别时返回逐项拒绝；高于或等于实时风险时才创建任务。

## 批量选择与操作

选择栏显示：

> 已选择 X 个视频 · 已配置 Y · 已抽帧 Z · 已筛帧 A · 有标注 B

### 批量配置采样

选中项包含已有方案时，先显示选择弹窗：

- 推荐操作：“仅处理 N 个未配置采样的视频”。
- 覆盖操作：“处理全部 X 个选中视频”。

选择推荐操作后，只把未配置视频传给采样表单。选择覆盖全部后：

- 批量表单表示把一套新方案统一应用到全部目标，不尝试展示各视频原方案。
- 若包含已有采样帧视频，表单默认锁定，必须开启“强制修改采样方案”。
- 主按钮显示“覆盖保存”。

### 批量抽帧

选中项包含已有帧时，先显示选择弹窗：

- 推荐操作：“仅处理 N 个未抽帧视频”。
- 覆盖操作：“处理全部 X 个选中视频”。

选择覆盖全部时，以目标集合中的最高风险确定弹窗：任意视频已有标注或保存过筛帧变更，整批操作使用 `destructive` 强警告和 3 秒倒计时；否则使用 `light` 普通确认。

批量接口继续逐项接受或拒绝。提交完成后只清除成功项的选择，保留拒绝项，便于用户查看原因或重新确认。

## 任务期间的写入冻结

`extract_frames` 任务进入 `queued` 或 `running` 后，该视频禁止：

- 再次保存采样方案。
- 保存筛帧启停变更。
- 保存手动或单张自动标注草稿。
- 创建新的批量自动标注任务。

读取视频、帧和标注，播放视频以及查看工作台不受影响。相关写接口统一返回 `409` 和明确提示。任务成功、失败或取消进入终态后自动解除冻结。

抽帧任务创建仍受现有活动任务唯一约束；Worker 继续校验采样方案版本，并仅在新帧完整生成后原子发布。冻结用于避免用户在覆盖确认后又生成会被任务删除的新成果。

## 视频业务状态展示

保留 `Video.status = pending | ready | unavailable` 作为独立的媒体状态，不新增数据库业务状态列。视频列表恢复“业务状态”视觉字段，由 `Video`、`Task`、`SamplingPlan`、`has_annotations` 实时推导。

业务状态单元格由一个主状态标签、可选补充标签和一行详情组成。颜色不是唯一表达方式，所有标签保留文本。

主状态按以下优先级选择：

1. 活动任务：等待导入、导入中、等待抽帧、抽帧中、等待自动标注、自动标注中。
2. 晚于资源更新时间的失败或取消任务。
3. 媒体等待导入或媒体不可用。
4. `version != applied_version && extracted_frames > 0`：待重新抽帧。
5. 已完成抽帧：已采样。
6. 已配置但未抽帧：待抽帧。
7. 可用且未配置：可配置采样。

补充标签可以同时显示，避免单一枚举丢失重叠信息：

- `frame_revision > 1`：已筛帧。
- `has_annotations`：有标注。
- `video.enabled == false`：视频停用。

详情示例：

- `待抽帧 · 预计 120 帧`
- `待重新抽帧 · 当前 80 帧，新方案预计 120 帧`
- `已采样 · 80 帧`
- `已采样 · 62/80 帧启用`

展示字符串不参与权限、按钮禁用、任务参数或后端状态判断。由此恢复状态字段不会改变现有功能，也不会引入老版不可逆状态机。

## 错误与并发处理

- 前端列表状态仅用于预览；所有覆盖资格由服务端重新检查。
- 批量请求允许部分成功，拒绝项返回稳定错误代码和用户可读原因。
- 实时风险升级、活动任务、方案版本变化和帧修订冲突返回 `409`，不进行对应视频的部分写入。
- 高风险确认不代表跳过 Worker 的方案版本校验。
- 重抽帧成功后旧 Frame 记录及其级联标注被替换，所有新帧初始为启用；确认文案必须明确该结果不可撤销。

## 验证范围

后端测试覆盖：

- 三种采样方案覆盖级别及混合批量部分拒绝。
- `none`、`light`、`destructive` 抽帧级别和实时风险升级。
- 有标注或保存过筛帧变更任意一项触发强风险。
- 抽帧活动期间采样配置、筛帧、手动标注和自动标注写入返回 `409`。
- 失败或取消保留原帧，成功重抽帧替换帧、标注及启停状态。
- 视频列表以单次聚合查询返回 `has_annotations`，不产生逐视频查询。

- 单视频表单预填、覆盖提示、强制修改开关和按钮文案。
