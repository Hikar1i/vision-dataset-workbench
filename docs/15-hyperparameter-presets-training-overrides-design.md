# 可编辑超参数预设与训练任务实时覆盖设计

状态：功能实现与验收完成。`UI/UX REVIEW PASSED`（2026-08-19，代码基线 `0823413`）。

## 1. 目标与边界

本次把超参数模板从“创建后不可变的训练资源”调整为“可编辑的参数预设”，并允许训练草稿在任务默认层和模型独立层实时编辑核心或完整超参数。

目标：

- 用户创建的模板可原地编辑，也可派生为新模板；系统模板保持只读。
- 训练草稿按模板最新内容计算未覆盖参数，同时保留用户显式覆盖。
- 已启动任务只使用启动时冻结的完整参数快照，后续模板修改不产生影响。
- 模板页面、训练任务快速覆盖卡和完整编辑弹窗复用同一套字段、校验和 RAW YAML 逻辑。

不实现：

- 模板完整修改历史、回滚或 revision 表；
- WebSocket/SSE 实时推送；
- 已启动任务的参数变更；
- 新的参数目录或新的训练框架。

## 2. 核心语义

模板 ID 在草稿阶段只表示“当前选择的预设来源”，不是训练执行时的强绑定配置。草稿页面读取模板最新版本，再叠加稀疏覆盖。启动训练时解析、校验并冻结最终参数，训练进程只读取快照。

模板增加轻量版本机制：

- `version` 初始为 1，每次成功编辑加 1，用于乐观并发；
- `updated_at` 创建时等于 `created_at`，编辑时更新；
- 不保存完整历史，因为训练模型已有完整 `template_snapshot`，足以审计实际运行参数。

系统模板继续只读。用户模板仅创建者或系统管理员可编辑和删除；所有认证用户仍可浏览任意模板并基于它创建派生模板。

## 3. 数据模型

### 3.1 超参数模板

`hyperparameter_templates` 增加：

| 字段 | 含义 |
| --- | --- |
| `version` | 正整数，默认 1；每次编辑加 1 |
| `updated_at` | 最近编辑时间；迁移时回填为 `created_at` |

`derived_from_id` 只记录创建时的派生来源，原地编辑不得修改该字段。

### 3.2 任务默认覆盖

`training_tasks` 增加：

- `default_epochs_override`；
- `default_batch_mode_override`；
- `default_batch_value_override`；
- `default_image_size_override`；
- `default_extra_parameters_override`。

前四项沿用现有模型核心覆盖语义。`default_extra_parameters_override` 为可空 JSON 文本。

### 3.3 模型覆盖

`training_models` 保留现有四个核心覆盖字段，仅增加 `extra_parameters_override` 可空 JSON 文本。

模型选择“继承任务默认”时，完整继承任务最终超参数，不应用模型休眠的模板和覆盖。切换回独立模板时恢复此前模型模板与覆盖。

### 3.4 附加参数差异格式

```json
{
  "version": 1,
  "set": {
    "lr0": 0.005,
    "mosaic": 0.8
  },
  "remove": ["patience"]
}
```

约束：

- `set` 与 `remove` 的键不得重复；
- 只能包含 Detect 参数目录中的非系统控制键；
- 三项核心键 `epochs`、`batch`、`imgsz` 不得写入附加参数差异；
- `set` 值按目录类型和范围校验；
- `remove` 表示从模板有效参数中明确移除该附加参数；
- 空差异规范化为 `null`。

## 4. 参数解析顺序

### 4.1 任务默认

1. 读取 `default_template_id` 对应模板的最新有效参数；
2. 应用任务默认核心覆盖；
3. 对附加参数先执行 `remove`，再执行 `set`；
4. 使用现有 Detect 目录重新严格校验完整结果。

### 4.2 模型继承

模型 `template_id` 为空时，直接使用任务默认的最终参数，不再应用模型休眠覆盖。

### 4.3 模型独立

1. 读取模型所选模板最新有效参数；
2. 应用模型核心覆盖；
3. 应用模型附加参数差异；
4. 不叠加任务默认覆盖。

### 4.4 启动快照

训练启动事务把以下内容写入 `training_models.template_snapshot`：

```json
{
  "id": "template-uuid",
  "name": "高精度检测模板",
  "version": 3,
  "updated_at": "2026-08-18T08:00:00Z",
  "parameters": {
    "epochs": 240,
    "batch": 8,
    "imgsz": 1280,
    "lr0": 0.005
  }
}
```

已启动和已完成任务的页面、调度和发布流程只读取快照。历史旧快照没有版本时显示 `—`，不批量改写。

## 5. 模板 API

新增：

`PATCH /api/v1/hyperparameter-templates/{id}`

请求包含当前 `version`、名称、描述、三项核心参数和完整附加参数。服务端执行：

1. 校验模板存在、未删除且当前用户可管理；
2. 拒绝系统模板；
3. 按版本执行乐观并发校验；
4. 使用现有参数目录规范化完整配置；
5. 校验活动模板名称唯一；
6. 更新内容、`catalog_version`、`updated_at` 并将 `version + 1`。

错误语义：

- 403：无编辑权限或系统模板；
- 404：模板不存在或已删除；
- 409：版本冲突或活动模板重名；
- 422：字段或参数校验失败。

模板响应增加 `version` 和 `updated_at`。训练资源接口中的模板增加版本、更新时间、完整有效参数、三项核心值和附加参数，以支持训练页本地解析和显示。

## 6. 训练草稿 API

创建和更新训练任务请求、任务详情响应增加任务默认覆盖字段；模型输入与响应增加 `extra_parameters_override`。

保存草稿时服务端规范化覆盖格式，并以当前模板为基线验证可解析的最终参数。模板后续可能再次变化，因此启动训练时仍必须重新解析和校验。

训练任务继续使用现有 `version` 做草稿更新冲突控制。

## 7. 模板页面

### 7.1 列表和详情

- 列表增加“编辑时间”列；
- 模板名称旁显示 `vN`，不新增单独版本列；
- 详情页显示创建时间、编辑时间和版本；
- 用户模板始终提供“详情 / 派生”，仅创建者或系统管理员额外看到“编辑 / 删除”；
- 系统模板操作为“详情 / 派生”。

### 7.2 新建、编辑和派生

编辑器继续采用左侧表单、右侧 RAW YAML 的双栏布局，并拆出可复用的完整配置编辑组件和核心参数字段组件。

- 新建页：`清空`、`创建模板`；
- 编辑页：`保存当前模板`、`派生模板`；
- 派生页：载入来源内容并创建新模板；
- 清空会清除名称、描述、附加参数、RAW 未解析状态和错误；核心值恢复 `epochs=100`、`image size=640`、`batch=auto`；
- 清空不删除派生上下文的 `derived_from_id`；
- 派生时打开命名确认框，默认“原模板名称 - 派生”。

编辑保存携带载入时的模板版本。409 冲突时保留用户内容，提示重新载入，不自动覆盖其他编辑者的修改。

## 8. 训练任务页面

### 8.1 任务默认超参数卡

未选择模板时只显示模板下拉框。选择后显示：

- 模板名称、版本和核心值摘要；
- “覆盖核心参数”开关；
- 核心参数字段；
- “编辑完整超参数”按钮；
- 持久状态提示。

标准布局复用模板编辑器字段：

- 第一行：`epochs + image size`；
- 第二行：`batch size`。

关闭核心覆盖只清除三项核心覆盖，不删除完整编辑产生的附加参数差异。

### 8.2 模型超参数卡

- `继承任务默认`：只显示继承来源、版本和覆盖摘要，不提供核心覆盖或完整编辑；
- 选择独立模板后才显示覆盖卡和完整编辑入口；
- 半宽模型卡复用同一核心参数组件的 compact 变体，三个控件纵向组织。

### 8.3 切换模板

没有覆盖时直接切换。存在覆盖时显示确认弹窗：

- “保留覆盖并应用到新模板”；
- “清空覆盖并使用新模板”；
- “取消”。

保留路径使用相同稀疏差异叠加到新模板，并立即验证结果；验证失败时不切换。

## 9. 完整编辑弹窗

弹窗直接复用模板新建/编辑页的核心字段、附加参数和 RAW YAML 编辑组件。初始完整配置由最新模板与当前覆盖合并得到。

RAW 有未解析修改或校验失败时禁用所有应用和保存动作。

三个动作：

### 9.1 本次应用

- 不修改模板；
- 比较编辑结果与当前模板，保存稀疏覆盖；
- 更新当前训练表单；
- 显示“已应用 N 项修改 · 保存草稿后持久化”。

### 9.2 应用并保存

- PATCH 当前用户模板；系统模板不显示此动作；
- 当前训练配置继续引用更新后的模板；
- 当前层已被模板吸收的覆盖清空；
- 显示“已应用并更新模板 · vN”；
- 训练表单仍由页面“保存草稿”统一持久化。

### 9.3 应用并派生

- 弹出命名确认框；
- 创建包含当前编辑结果的新模板；
- 当前训练配置切换到新模板并清空当前层覆盖；
- 显示“已应用派生模板「名称」”；
- 若用户放弃训练草稿，新模板仍作为独立资源保留。

## 10. 模板同步

训练页重新获得浏览器焦点时重新拉取训练资源。发现所选模板版本变化后：

- 自动更新模板资源；
- 以新模板重算未覆盖参数；
- 保留现有稀疏覆盖；
- 显示“模板已更新至 vN，已保留 X 项覆盖”。

同页“应用并保存”使用 API 返回值立即更新本地模板资源。

## 11. 验收结果

- 后端全量测试：208 项通过；
- 前端全量测试：52 个文件、177 项通过；
- 前端生产构建通过，仅保留既有 `:deep` 与 chunk-size 警告；
- Chrome 在 1920×1080、2560×1440 下完成模板列表、新建/编辑、任务/模型覆盖、完整编辑弹窗、模板切换保护和权限边界核验；
- 独立 reviewer 确认两种分辨率无页面级横向溢出、无低于 13px 的可见叶文本，交互反馈、动效、reduced-motion 与可访问名称符合 `docs/10-ui-ux-design-system.md`。

完整编辑弹窗打开期间不覆盖其工作副本。提交前检查模板当前版本；版本变化时保留编辑内容并要求重新载入基线。

## 11. 错误与状态处理

- 网络失败时不关闭弹窗、不清空表单；
- 模板失效时保留草稿 ID并显示明确错误，阻止保存并启动；
- 模板切换后的覆盖无法通过校验时保持原模板；
- 派生名称冲突时保留命名框和编辑内容；
- 成功动作同时显示 Toast 和卡片内持久状态，不能只依赖短暂消息；
- 离开有未保存训练表单或模板编辑器时沿用浏览器离开确认。

## 12. 迁移与兼容

- 模板 `version` 回填 1，`updated_at` 回填 `created_at`；
- 新增训练覆盖字段默认为 `null`；
- 现有模型四项核心覆盖无需转换；
- 历史快照、历史训练和已发布模型不改写；
- 不改变现有 Detect 参数目录和 RAW 严格校验规则。
