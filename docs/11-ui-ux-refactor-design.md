# UI/UX 整体重构设计

状态：设计已批准，`UI/UX REVIEW PASSED`。

## 背景

当前主要功能已经完成，但不同时期实现的按钮、组件、布局、配色和动效存在明显差异。Chrome 现状检查确认了以下问题：

- 左侧导航使用深色高密度语言，右侧页面同时混用默认 Element Plus、平面表格、卡片和不同圆角规则。
- 页面标题、统计、页签和操作分散在多条横栏，层级与顺序不稳定。
- 当前正文基础字号为 15px，标题为 22px，但面包屑、子导航、说明和表头大量使用 12–13px；源码中存在 76 处 9–12px 字号声明。
- 按钮 hover 与 active 反馈不统一，部分 hover 产生位移；展开收起和页面切换不够自然。
- 普通图标混用 Element Plus、Ant Design 和手绘 SVG。

## 目标

- 在不改变核心业务功能和大方向布局的前提下，重塑并固化统一设计系统。
- 统一右侧功能区的面包屑、返回、标题、统计、子页签、功能按钮和主区域层级。
- 提高字体与控件尺寸，改善 1920×1080 和 2560×1440 下的可读性和空间利用率。
- 让 hover、press、页签、面板和侧栏动效明确、克制且可关闭。
- 把 UI/UX 约束纳入仓库规则，并通过独立 Chrome 评审门禁防止后续漂移。

## 非目标

- 不修改 API、路由、业务状态、权限规则或服务端数据流。
- 不重写完整组件库，不增加新的 UI 依赖。
- 不实现移动端和窄屏适配。
- 不改变标注和筛帧工作区的工具栏、画布、缩略图轨道和属性区总体布局。

## 选择的方案

采用“设计令牌 + 共享页面骨架 + 分批迁移”。

仅修改全局 CSS 无法消除页面内硬编码差异；完整重写组件库风险和投入过高。当前方案通过全局令牌、一个共享 `PageHeader` 和现有 `AppShell`、`ProjectLayout`、`FocusLayout` 完成统一，避免新增不必要抽象。

## 视觉方向

- 浅色管理页采用 `Soft UI Evolution × Drill-Down Analytics`。
- 深色标注和筛帧工作区使用同一设计系统的专注变体。
- 精确颜色、字体、字号、形状、组件和动效规则以 [UI/UX 设计系统](10-ui-ux-design-system.md) 为准。
- 保留当前字体性格，使用 `Inter`、`Bahnschrift` 与已安装的 Noto CJK 字体，不引入网络字体。

## 架构与组件

### AppShell

- 保留左侧菜单和右侧功能区。
- 侧栏 256px，可收起至 72px；去除移动端抽屉逻辑和移动断点样式。
- 顶栏保留任务中心和用户菜单，面包屑改为真实链接。
- 普通图标迁移到 `@element-plus/icons-vue`，领域专用 SVG 保留。

### PageHeader

当前 16 个页面重复使用 `content-toolbar`。新增一个共享 `PageHeader.vue`，提供标题、返回、统计、操作和可选页签插槽。组件只负责结构和视觉，不读取业务数据，也不持有页面状态。

### ProjectLayout

继续加载项目、维护最近项目和提供四个项目子页签。项目身份区、页签与子页面头部使用同一令牌，形成连续头部。项目页面的数据请求和事件保持不变。

### FocusLayout

继续承载标注和筛帧整页工作区。使用深色令牌统一工具栏、按钮、状态、面板和覆盖信息，不改变编辑、快捷键、画布与保存流程。

## 页面族

### 列表页

适用于系统总览、数据集项目、模型项目、超参数模板、训练任务和用户管理：

`面包屑 → 标题与总数 → 主操作 → 可选页签 → 筛选或统计 → 主区域`

### 详情页

适用于模型项目详情、模型详情、超参数详情、训练任务详情和训练模型详情：

`面包屑 → 返回与标题 → 可用数量或状态 → 操作 → 摘要 → 主区域`

### 数据集项目子页

适用于原始数据、标签管理、数据集管理和项目设置：

`项目返回入口、项目名称与权限 → 四个子页签 → 当前页标题、统计和操作 → 主区域`

### 配置与认证页

大模型配置的配置列表与默认设置使用统一分段页签。登录、注册和初始化保留独立流程布局，但使用相同字体、配色、表单、按钮和反馈。

## 数据流与错误处理

- 页面继续从现有 API 模块加载数据，路由参数和事件接口不变。
- `PageHeader` 只接收展示数据和插槽，不发起请求。
- 加载、空状态和错误状态继续使用现有状态分支；本次只统一视觉与文案层级。
- 删除、覆盖、训练和批量操作的确认逻辑、倒计时和错误映射不得弱化。

## 实施顺序

1. 固化全局颜色、字体、尺寸、圆角、阴影和动效令牌。
2. 重构 AppShell、可点击面包屑和普通图标。
3. 新增 PageHeader，并迁移列表页和详情页。
4. 统一 ProjectLayout、项目四个子页和大模型配置页签。
5. 统一表格、卡片、表单、弹窗、抽屉和状态反馈。
6. 重构登录、注册和初始化页。
7. 应用深色专注令牌到标注和筛帧工作区。
8. 在 Chrome 中完成两档分辨率自检。
9. 由独立 reviewer 执行 UI/UX Chrome 复核并更新评审标记。

## 风险与控制

- 全局 Element Plus 变量可能影响复杂表单：先修改令牌，再逐页 Chrome 核对。
- 提升字号可能造成高密度台账溢出：允许调整列宽和省略策略，不缩小可读文字。
- 图标迁移可能改变可访问名称：保留或补充 `aria-label`、`title` 和现有测试选择器。
- 深色工作区可能出现对比度退化：使用专用深色令牌，不直接反转浅色页面。
- 2560px 可能拉伸内容：表格、画布和多栏面板吸收空间，文本和控件保持稳定尺寸。

## 已批准决策

- 选择方案 2：设计令牌 + 共享页面骨架 + 分批迁移。
- 选择 B：Soft UI Evolution。
- 普通管理页浅色，标注和筛帧使用同设计系统深色变体。
- 登录、注册和初始化纳入重构。
- 仅支持 1920×1080 和 2560×1440，不考虑移动端。
- 2560px 充分利用全宽。
- 动效克制明确，不使用弹跳、漂浮和整页入场。
- 保持当前字体性格并整体提高字号。
- 使用永久设计文档约束后续实现，并设置独立 UI/UX review 门禁。
