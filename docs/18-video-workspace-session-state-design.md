# 视频工作区会话状态设计

状态：已确认，待实施。

## 问题与根因

在线视频标注使用独立的 `FocusLayout` 路由，不在 `AppShell → ProjectLayout → ProjectVideosView` 组件树内。进入标注页时，视频列表和筛帧弹窗会被卸载；关闭标注后重新导航到视频列表会创建全新的组件实例，因此以下前端局部状态恢复默认值：

- 视频列表当前页恢复为第 1 页。
- 视频列表每页数量恢复为 50。
- 筛帧缩略图比例恢复为 `1.00×`。

这不是浏览器刷新，但组件生命周期效果等同于重新打开页面。

## 目标

- 在线标注往返或同一 SPA 会话内组件重挂载后，恢复视频列表当前页和每页数量。
- 同一视频重新打开筛帧工作台时，恢复其缩略图比例。
- 返回列表后仍请求最新数据，不缓存视频响应或筛帧业务数据。
- 不修改后端、API、数据库或 URL。
- 完整页面刷新和成功退出登录后恢复默认值。

## 非目标

- 不保留复选框选择、弹窗开关、预览位置、筛帧页码、未保存筛帧草稿等临时状态。
- 不改变在线标注的焦点路由和页面布局。
- 不引入 `KeepAlive`、全局状态库、`localStorage` 或 `sessionStorage`。

## 方案

新增一个前端模块内存状态模块，使用普通内存映射保存两类状态：

- `project:{projectId}:videos`：视频列表的 `page` 与 `pageSize`。
- `project:{projectId}:video:{videoId}:frames`：筛帧缩略图比例。

视频列表创建时读取对应项目的状态，并用其发起首次列表请求。每次列表请求成功后，以接口返回的 `page`、`page_size` 更新缓存；列表请求失败时不覆盖上一次成功状态。

筛帧弹窗打开时按项目和视频读取缩略图比例。用户提交 Slider 变化时同时更新当前布局和缓存；拖动但尚未提交时不写入缓存。

状态模块提供统一清理函数。成功退出登录时，在退出请求成功后、进入登录页前清理；退出失败时保持状态。完整刷新会自然重建模块并清空状态。

## 备选方案

- URL 查询参数：适合分页，但缩略图比例属于局部显示偏好，写入 URL 会污染路由并耦合标注页的返回协议。
- 调整路由并保活视频列表：能够保留更多局部状态，但需要重构 `AppShell`、`FocusLayout` 和嵌套路由，改动与当前问题不成比例。
- 浏览器存储：能够跨刷新保留，但超出已确认的“当前前端会话”边界。

## 测试与验收

- 视频列表切换页码和每页数量后，组件卸载并重挂载，首次请求使用原值。
- 不同项目的视频列表状态互不影响。
- 同一视频的筛帧缩略图比例在组件重挂载后恢复，不同视频互不影响。
- 成功退出清空状态；退出失败不清空。
- 完整前端测试和生产构建通过。
