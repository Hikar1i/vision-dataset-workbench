# 路由驱动的标注覆盖层设计

状态：已确认，待实施。

## 问题与根因

筛帧工作台是 `ProjectVideosView` 内部的全屏 Dialog。打开和关闭期间，视频列表以及负责纵向滚动的 `.app-content` 元素始终挂载，因此列表分页、筛帧比例和滚动位置自然保留。

在线标注当前位于 `AppShell` 之外的独立 `FocusLayout` 路由。进入标注页会卸载 `AppShell → ProjectLayout → ProjectVideosView` 整棵组件树，退出时再重新创建。上一版模块内存状态只恢复了分页和筛帧比例，无法保留已经被销毁的滚动容器，所以返回后仍会出现页面重新载入感并回到顶部。

## 目标

- 标注页面保持现有 URL 和全屏专注布局。
- 从视频列表进入标注时，视频列表组件和 `.app-content` 滚动容器不卸载。
- 关闭标注或使用浏览器后退后，显示点击标注前的同一列表实例与滚动位置。
- 浏览器前进可以重新打开标注覆盖层。
- 直接访问标注 URL 时仍可正常加载，关闭后安全返回视频列表。
- 删除不再需要的视频工作区模块内存状态及其退出清理逻辑。
- 不修改后端、API、数据库或标注业务数据流。

## 非目标

- 不缓存标注草稿、视频响应或其他页面实例。
- 不使用根级 `KeepAlive`。
- 不把滚动位置写入 URL、后端或浏览器存储。
- 不改变筛帧工作台结构。

## 路由与组件结构

标注 URL 仍为 `/projects/:id/videos/:videoId/annotation`，但路由记录移到 `project-videos` 下面：

```text
AppShell
└── ProjectLayout
    └── ProjectVideosView
        └── FocusLayout（全屏覆盖层）
            └── AnnotationWorkbenchView
```

`ProjectVideosView` 通过嵌套 `RouterView` 接收标注子路由，并 Teleport 到 `body`。`FocusLayout` 使用固定定位覆盖视口，层级低于 Element Plus 的 Dialog/MessageBox 浮层，保证标注内部弹窗仍显示在其上方。

`ProjectLayout` 不再使用完整的 `route.name` 强制给当前项目子页换 key。进入 `video-annotation` 时，当前项目一级子页仍是 `project-videos`，因此必须复用原 `ProjectVideosView` 实例；切换标签管理、数据集管理等一级子页仍由不同组件类型正常切换。

## 导航与历史

从视频列表点击标注时，使用命名路由进入标注，并在该历史记录中写入来源标记。

- 有来源标记：关闭按钮先保存当前标注，成功后调用 `router.back()`，回到原列表历史记录。浏览器前进可重新进入标注。
- 无来源标记：说明用户直接打开或刷新了标注 URL，关闭时使用 `router.replace()` 返回当前项目视频列表，避免退到站外或登录页。
- viewer 校验失败：继续使用 `replace()` 返回视频列表。
- 保存失败：保持标注覆盖层打开，不执行导航。

标注工作台增加路由离开守卫。浏览器后退、侧栏导航或其他 SPA 路由离开前先调用现有原子保存逻辑；保存失败时取消导航并保持覆盖层打开。现有 `beforeunload` 继续负责刷新、关闭标签页等浏览器级离开提示。

## 删除上一版补丁

路由覆盖层使 `ProjectVideosView` 和 `FramesDialog` 在标注往返期间保持同一实例，因此删除：

- `videoWorkspaceState.ts` 及其测试。
- 视频列表的分页状态读取与回写。
- 筛帧比例的模块状态读取与回写。
- `AppShell` 的视频工作区状态清理。
- 对应代码规范、测试策略和旧设计文档内容。

筛帧比例仍保留现有组件内行为：Dialog 关闭只重置临时选择和预览状态，不重置已提交的比例。

## 测试与验收

- 路由匹配确认标注位于视频列表子路由下，URL 不变。
- 从视频列表进入标注时，`ProjectVideosView` 只挂载一次。
- `.app-content` 元素身份和 `scrollTop` 在进入、关闭、后退及前进过程中保持。
- 关闭按钮在列表来源场景调用后退；直接访问场景使用替换返回。
- 浏览器后退会先保存当前草稿；保存失败时取消导航，viewer 仍安全重定向。
- 筛帧现有测试继续通过，不再依赖模块内存。
- 完整前端测试和生产构建通过。

## 备选方案

- 缓存并恢复 `scrollTop`：仍会卸载和重新请求页面，只能遮盖结果，不能消除根因。
- 根级 `KeepAlive`：缓存范围过大，可能保留不相关页面和陈旧业务状态。
- 将标注改造成普通 Dialog：需要重写大量路由参数和直接访问逻辑；嵌套路由覆盖层可以复用现有工作台。
