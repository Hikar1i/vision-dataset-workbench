# 多数据集标签重映射设计

状态：已完成需求评审，待依据本文制定实施计划。

## 1. 背景与目标

当前训练任务只能为任务或单个训练模型选择一个数据集导出。实际训练经常需要组合多个项目的数据集，而不同数据集的类别索引可能冲突：例如数据集 A 的 `car=0`、`plane=1`，合并后的训练类别可能是 `car=2`、`plane=5`。Ultralytics YOLO 的检测数据集配置不能为每个来源声明任意类别索引映射；YOLO TXT 第一列必须已经是最终连续类别索引。

本功能在不修改原始数据集导出、不引入自定义 Ultralytics Trainer 的前提下，提供：

- 任务默认数据集和模型级数据集均支持单数据集或多数据集配置；
- 同名类别自动归组、类别筛选和顺序调整；
- 训练启动后先执行独立的“准备训练数据”阶段；
- 使用图片硬链接和重写后的 YOLO TXT 生成任务级不可变训练数据；
- 准备状态、进度、日志、失败和重试在训练任务中可见。

## 2. 已确认的产品规则

### 2.1 类别规则

- 目标类别名只读，不提供重命名或语义合并。
- 去除类别名首尾空白后按精确名称归组，区分大小写。
- 多数据集模式允许只选择一个数据集，用于类别筛选或重排。
- 删除目标类别只删除对应标注行，不删除图片；没有剩余标注的图片作为负样本保留，并生成空标签文件。
- 不自动去重重复图片，仅提示潜在重复，不阻止保存或训练。
- 最终保存的目标类别索引必须连续，从 `0` 开始；弹窗编辑过程中允许暂时出现空洞。

### 2.2 模式与继承

- 任务默认数据集支持 `single` 和 `multi` 两种模式。
- 模型数据集支持 `inherit`、`single`、`multi` 三种模式。
- 模型选择“继承任务默认”时，启动任务才解析当时有效的任务默认配置。
- “编辑并覆盖”以任务默认多数据集配置的深拷贝作为模型工作副本。
- “恢复任务默认”清除模型覆盖并回到 `inherit`。
- 关闭已有多数据集配置只停用，不删除；再次打开恢复上次保存值。
- 首次打开多数据集配置后取消，开关回到关闭并保留之前的单数据集选择。
- 旧任务按单数据集模式兼容：模型无 `dataset_export_id` 表示继承，有值表示自定义单数据集。
- 新建任务和未启动草稿可编辑；已启动任务只展示启动时快照。

### 2.3 训练与拆分

- “训练模式”选择器移到“训练模型与执行顺序”区域最上方。
- 保留每个来源导出的既有拆分：`train` 合并到 `train`、`val` 合并到 `val`、存在 `test` 时合并到 `test`，不重新随机拆分。
- 整个任务先准备完全部多数据集配置，再进入训练队列；单数据集模型不提前启动。
- 准备阶段不申请 GPU。
- 同一任务内，完全相同的有效配置只准备一次；不同任务之间不共享缓存。

## 3. 页面信息架构

### 3.1 新建/编辑训练任务

页面沿用现有左侧导航和右侧工作区，使用统一 `PageHeader`。主表单自上而下为：

1. **基本信息**：任务名称与任务编码同一行，描述独占一行；编码失焦后显示检查中、可用、冲突或检查失败。
2. **任务默认资源**：数据集、超参数、计算资源分别独占一行，避免窄列挤压。
3. **训练模型与执行顺序**：训练模式选择器位于本区最上方，其后为有序模型卡片。

任务默认数据集启用多数据集后，原级联选择器替换为摘要卡：展示数据集数量、图像数量、目标类别数量、配置状态，并提供“配置/查看映射”。

模型卡片的数据集行明确显示三种状态：

- 继承任务默认：只读摘要，提供“编辑并覆盖”；
- 自定义单数据集：显示单个导出选择器；
- 自定义多数据集：显示多数据集摘要，提供“配置映射”；

卡片始终提供“恢复任务默认”，但继承状态下禁用并说明原因。

### 3.2 类别重映射弹窗

弹窗使用大尺寸桌面布局，主体左右分栏：

- 左栏：项目/数据集搜索、可展开项目树和数据集复选；
- 右栏上部：已选数据集摘要与可折叠 chip 列表；
- 右栏下部：类别映射表。

映射表列为：目标索引、目标类别名、来源类别、操作。目标类别名只读；来源类别最多显示两行，超出后显式展开。操作只包含上移、下移和删除；表头提供“自动整理索引”和“恢复已删除类别”。

底部固定展示校验结果和保存/取消按钮。错误应说明原因与修复动作；重复样本仅显示警告。

### 3.3 训练任务详情

详情页新增独立“准备训练数据”阶段，展示：

- 状态：等待、准备中、准备失败、已完成、已取消；
- 当前步骤、文件进度和耗时；
- 准备日志入口；
- 失败原因和“重试准备”；
- 已完成产物的配置哈希、数据集/图像/标注统计。

准备进度与 epoch 训练进度分离，不能复用现有训练 `progress` 字段。

## 4. 交互细节

### 4.1 映射初始化与编辑

1. 按数据集选择顺序读取来源导出清单。
2. 类别名去除首尾空白后，精确且区分大小写地自动归组。
3. 既有目标类别保持当前顺序；新出现类别按数据集选择顺序、再按来源索引追加。
4. 取消选择数据集后移除其来源；没有任何来源的目标行自动消失。
5. 上移/下移交换相邻目标索引。
6. 删除目标行可产生临时索引空洞。
7. “自动整理索引”按当前可见顺序压缩为连续索引。
8. “恢复已删除类别”恢复仍有来源的类别，保持现有行顺序，并优先填入最小空洞。
9. 弹窗使用工作副本；取消不修改外层已保存配置。

### 4.2 保存校验

保存前必须满足：

- 至少选择一个可用数据集导出；
- 至少保留一个目标类别；
- 目标索引连续且从 `0` 开始；
- 目标类别名唯一，且均来自当前所选导出的有效标签；
- 所选导出仍存在且处于可用状态。

数据可能重复时显示警告但允许保存。后端在保存和启动时均重新校验，数据库唯一约束负责处理编码可用性检查后的并发冲突。

### 4.3 动效与无障碍

- hover/press 使用 120–180ms；面板和来源展开使用 180–240ms；弹窗内部展开使用 240–280ms。
- 交互控件有明确 hover、active、focus-visible 和 disabled 状态。
- 展开控件提供 `aria-expanded`/`aria-controls`；模式切换使用原生单选语义；图标按钮提供可访问名称。
- 遵守 `prefers-reduced-motion`，关闭动画不影响状态可见性。

## 5. 数据契约

### 5.1 编辑态配置

编辑态只保存无法从数据集导出清单推导的事实：

```json
{
  "version": 1,
  "dataset_export_ids": ["export-a", "export-b"],
  "target_classes": ["person", "car", "plane"]
}
```

- `dataset_export_ids` 有序，决定新增类别和同名来源的稳定顺序。
- `target_classes` 有序、唯一，数组位置就是最终类别索引。
- 来源项目名、数据集名、来源类别索引和统计信息均从导出清单推导，不重复持久化。
- 被删除的类别不在 `target_classes` 中；不单独维护删除列表。

### 5.2 启动快照

启动时为每个模型解析有效配置并生成不可变快照，写入现有 `TrainingModel.dataset_snapshot`：

```json
{
  "version": 1,
  "kind": "multi",
  "config_hash": "sha256:...",
  "prepared_storage_path": "...",
  "target_classes": [
    {"index": 0, "name": "person"},
    {"index": 1, "name": "car"}
  ],
  "sources": [
    {
      "dataset_export_id": "export-a",
      "project_id": "project-a",
      "project_name": "项目 A",
      "dataset_name": "数据集 A",
      "manifest": {"version": 1},
      "class_map": {"0": 1, "1": 0}
    }
  ],
  "stats": {
    "images": 50000,
    "labels": 128000,
    "negative_images": 320,
    "ignored_annotations": 2400
  }
}
```

已启动任务只读展示该快照，不随来源数据集后续变化。

## 6. 数据库与 API

### 6.1 最小字段变更

`TrainingTask`：

- `default_dataset_mode`: `single | multi`，默认 `single`；
- `default_multi_dataset_config`: nullable JSON text；
- 状态新增 `preparing`、`preparation_failed`；
- 保留现有 `default_dataset_export_id`，多数据集启用时也不清空。

`TrainingModel`：

- `dataset_mode`: `inherit | single | multi`；
- `multi_dataset_config`: nullable JSON text；
- 状态新增准备阶段状态；
- 保留现有 `dataset_export_id` 作为自定义单数据集覆盖。

新增 `TrainingPreparation`，每次任务启动最多一条当前准备记录：

- `id`, `training_task_id`, `status`, `phase`；
- `progress`, `processed`, `total`；
- `pid`, `worker_id`, `lease_expires_at`；
- `storage_path`, `error`, `created_at`, `started_at`, `finished_at`。

类别映射本身不拆成关系表，避免多表同步和无收益的查询抽象。

### 6.2 API 变更

- 训练资源接口为数据集补充总量、train/val/test 数量以及 `{index, name}` 标签列表。
- 新增任务编码可用性查询；前端失焦检查只改善反馈，创建/更新接口仍以数据库唯一约束为准。
- 创建/更新训练任务接受任务和模型的数据集模式及多数据集配置。
- 任务详情返回持久化配置、已启动快照和准备阶段对象。
- 新增准备日志读取和准备失败重试接口。

## 7. 训练数据准备流程

### 7.1 状态流

```text
draft -> preparing -> queued -> running -> completed
                  \-> preparation_failed -> preparing
                  \-> cancelled
```

启动请求先完成同步校验，再创建准备记录并启动独立子进程。准备成功后才创建/排队 `TrainingRun`，现有 GPU 调度器无需承担文件准备工作。

### 7.2 产物生成

每个唯一有效配置执行：

1. 读取并固定所有来源导出清单，计算规范 JSON 的 SHA-256。
2. 在任务目录创建 `.preparing-<uuid>` 临时目录。
3. 按来源保留 `train`/`val`/`test` 拆分。
4. 为图片创建硬链接；目标文件名包含来源导出前缀，避免重名。
5. 逐行读取 YOLO TXT，仅重写第一列类别索引；丢弃被排除类别的标注行，坐标原样保留。
6. 为没有剩余标注的图片写入空 TXT。
7. 生成连续 `names` 的 `dataset.yaml`、准备清单、统计和 `READY` 标记。
8. 校验后原子重命名到 `<config-sha256>` 目录。

硬链接失败不静默回退为全量图片复制，而是报告文件系统不兼容及处理建议，避免意外占满磁盘。当前受管导出和任务目录位于同一工作区，正常路径应满足硬链接条件。

### 7.3 性能预算

在当前本地 ext4/NVMe 上的 50,000 文件合成基准约为：

- 50,000 个图片硬链接：0.77 秒；
- 50,000 个两行标签读取和重写：2.22–2.45 秒；
- 理想基线合计约 3 秒。

该基准不代表生产承诺。正式设计预算为：本地 NVMe/ext4 5–30 秒，SATA 或高负载磁盘 20–90 秒，网络文件系统 1–5 分钟。启动前检查可用空间；空间增长主要来自重写标签和目录元数据，而非图片内容。

### 7.4 进度、日志与恢复

- 准备子进程按阶段写独立日志，详情页统一呈现 `[prepare]`、`[queue]`、`[train]` 前缀。
- 日志记录校验、硬链接数量、标签重写数量、忽略标注、负样本、YAML、最终校验和错误摘要；不逐文件刷日志。
- 进度事件每秒或每 500 文件最多更新一次。
- 准备失败不占用 GPU，清理临时目录并进入 `preparation_failed`。
- 取消时终止准备子进程并清理临时目录。
- 重试复用同任务内已有 `READY` 哈希产物；已完成产物随任务保留，供训练重试或恢复使用。

## 8. 错误处理

- 启动前重新校验来源导出状态、存储路径、清单版本、类别集合、索引连续性、配置哈希和磁盘空间。
- 数据集被删除、文件缺失、清单损坏、硬链接跨文件系统、空间不足等错误必须给出具体对象和处理动作。
- 任务编码检查失败不得误报“可用”；保存时出现并发冲突返回明确的编码重复错误。
- 准备失败可重试，不影响原始导出，也不产生半成品正式目录。
- 准备进度和训练 epoch 进度分别持久化和展示。

## 9. 测试与验收

### 9.1 自动化测试

- 纯逻辑：精确名称归组、选择顺序、新类别追加、删除/恢复/重排、连续索引和配置哈希。
- 标签转换：仅修改首列、坐标保持、排除标注、空负样本、未知来源索引报错。
- 服务/API：配置校验、任务继承、模型覆盖、旧草稿兼容、编码检查与唯一约束竞态。
- 准备流程：拆分保持、原子目录、取消/失败/重试、无 GPU 占用、同任务相同配置复用。
- 前端：首次开启取消、停用后恢复、工作副本取消、摘要展开、继承/覆盖切换和只读快照。

### 9.2 UI/UX 验收

实施时设置 `UI/UX REVIEW REQUIRED`，由独立 reviewer 按 `docs/10-ui-ux-design-system.md` 验收并显式使用 Chrome：

- `1920×1080` 和 `2560×1440` 下无页面或弹窗横向溢出；
- 弹窗左右栏、表头和数据列严格对齐，长文本省略且不侵占其他列；
- 所有可读文字不低于 13px，主要表单和按钮按 14–15px；
- hover、press、focus、展开收起和 reduced-motion 均有效；
- 错误、警告、空态、加载态和只读态不只依赖颜色表达。

## 10. 明确不做

- 不在原始数据集目录中修改 YOLO TXT；
- 不支持用户重命名类别或把不同名称语义合并；
- 不自动查重或删除重复图片；
- 不重新划分 train/val/test；
- 不跨任务共享准备产物；
- 不为 Ultralytics 编写自定义 Trainer；
- 不支持移动端或窄屏布局。
