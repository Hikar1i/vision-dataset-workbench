# 列表最近交互行高亮设计

状态：交互方案与适用范围已确认，等待实施。

## 问题

用户从高密度资源列表打开弹窗、进入详情页或执行行内操作后，返回列表时难以确认刚才
操作的是哪一条数据。视频人工筛帧最容易触发该问题：关闭全屏筛帧工作台后，多个外观
相近的视频行可能导致用户再次进入刚处理的视频。模型、训练任务和配置等资源列表也有
相同的定位需求。

已有业务状态不能代替最近交互提示。例如“已筛帧”表示视频保存过筛帧结果，不能说明
它是不是用户刚才打开的条目。服务端访问时间也不适合该需求：它会引入数据库和 API
变更，并把只对当前浏览器会话有意义的界面位置提示变成持久业务数据。

## 目标

- 用户点击某一行的可用操作后，以不突兀的浅色底纹标出该行。
- 每个列表独立保留一条最近交互记录，子列表按所属资源隔离。
- 弹窗关闭、列表刷新、分页切换、筛选切换和 SPA 路由往返后仍能恢复提示。
- 浏览器完整刷新后清空全部提示。
- 所有目标列表使用相同视觉和触发规则，不增加可见提示文字。
- 不修改后端、数据库或现有 API。

## 范围

| 列表 | 作用域 | 当前表格实现 |
| --- | --- | --- |
| 数据集项目列表 | `projects` | `VTable` / `VRow` |
| 数据集项目－原始数据 | `project:{projectId}:videos` | 自定义 grid 台账 |
| 数据集项目－数据集管理 | `project:{projectId}:datasets` | Element Plus `el-table` |
| 模型项目列表 | `model-projects` | `VTable` / `VRow` |
| 模型项目－模型列表 | `model-project:{projectId}:models` | `VTable` / `VRow` |
| 超参数模板列表 | `hyperparameter-templates` | `VTable` / `VRow` |
| 训练任务列表 | `training-tasks` | `VTable` / `VRow` |
| 训练任务详情－训练模型列表 | `training-task:{taskId}:models` | 按 GPU 分组的多个 `VTable` |
| 大模型配置列表 | `llm-configs` | `VTable` / `VRow` |

训练任务详情中的多个 GPU 表格共用一个任务级作用域，因此同一任务始终只高亮一个训练
模型。数据集项目、模型项目等父列表与其子列表使用不同作用域，进入子页面不会覆盖父
列表原有的最近交互记录。

用户与注册审批列表不在本次范围内；该模块后续将随角色、用户和权限体系重构。文件
选择器、标签排序、项目成员、任务中心、映射表和详情弹窗内的只读明细表也不启用该
能力。

## 交互规则

1. 只捕获行内操作区域中实际可点击的按钮或链接。表格内容、行选择框、启用开关、批量
   操作和页面工具栏不触发高亮。
2. 点击发生时立即记录该行，不等待弹窗关闭、路由返回或异步操作完成。取消确认框仍算
   一次交互。
3. 同一列表作用域只保存一个资源 ID。点击另一行操作后，高亮立即转移。
4. 禁用控件不产生点击事件，因此不会更新记录。
5. 删除成功后资源行消失，高亮自然不可见；无需选择另一行，也无需为已删除 ID 增加
   清理流程。
6. 列表重新请求、重排、分页或筛选时按稳定资源 ID 匹配。目标暂时不可见时不显示任何
   替代提示，重新进入包含该资源的列表状态后恢复高亮。
7. 不显示“刚刚筛帧”“最近访问”等可见标签，不改变按钮文案，不自动滚动列表，也不
   推断或突出“下一项”。

## 前端状态

新增一个小型模块级响应式映射，保存“列表作用域 → 最近交互资源 ID”。模块内存能够在
Vue 页面组件卸载后继续存在，因此从详情页、编辑页或标注工作台返回时仍能恢复行状态；
浏览器完整刷新会重新加载 JavaScript 模块并自然清空映射。

用户退出登录时也必须清空映射，防止同一浏览器标签页切换账号后继承上一账号的界面
状态。退出登录失败时不提前清空，成功后与其他当前用户状态一并清理。

状态不得写入 `localStorage`、`sessionStorage`、URL、Cookie 或服务端。无需过期时间、
容量回收或持久化迁移；作用域数量由固定目标页面和当前访问过的父资源决定，当前会话内
的数据量可忽略。

各页面显式提供作用域和行 ID。共享表格组件不自行推断路由，也不全局监听所有表格按钮，
避免未来新增表格后在没有业务确认的情况下自动获得该行为。

## 组件与页面接入

`VRow` 增加可选的最近交互状态，仅负责统一行样式和非可见状态语义，不直接访问共享
映射。使用 `VTable` 的七个目标页面负责：

- 根据自身作用域和资源 ID 判断 `VRow` 是否为最近交互行；
- 在 `.row-actions` 上使用捕获阶段点击处理，确认事件来自未禁用的 `button` 或 `a` 后
  先记录行 ID，再让原按钮逻辑继续执行。点击操作区空隙不更新记录。

原始数据视频台账复用相同状态类和操作区域捕获规则。数据集管理的主 `el-table` 通过
`row-class-name` 返回相同状态类，并对 Element Plus 单元格背景做薄适配；详情抽屉内的
类别和视频统计表不接入。

训练模型虽然分布在多个 GPU 表格中，所有行仍使用同一任务级作用域。实时轮询或操作后
重新加载模型对象不会丢失状态，因为匹配依据是模型 ID，而不是对象引用或行序号。

## 视觉与无障碍

最近交互行使用现有青色强调令牌的低透明度底纹，并保留原有文字、状态标签和按钮配色。
停用视频等已有行背景仍是基础背景，最近交互色作为其上方的透明叠层，不覆盖业务状态。
悬停可以短暂加强反馈，但移开后最近交互底纹必须保持。

底纹不得使用动画闪烁、整行位移、粗边框或强饱和颜色。除浅色底纹外，共享行提供非可见
的 `aria-current="true"` 状态；自定义视频台账使用相同语义。Element Plus 主表在资源名
单元格提供视觉隐藏的“最近交互”状态文本，不向表格新增可见文字列。

## 错误和边界处理

- 操作失败不回滚最近交互状态，因为该状态表达交互对象而不是操作结果。
- 用户取消删除、覆盖或其他确认框时仍保留该行。
- 操作导致行被筛选条件隐藏时不自动改变筛选条件。
- 一个页面存在多个目标列表时必须使用明确作用域；非目标明细表不得继承父列表状态。
- 资源 ID 是唯一匹配依据；显示名称、排序、分页位置和业务状态不参与判断。

## 验证

- 状态模块测试：不同作用域相互隔离，同一作用域后写入的 ID 替换旧 ID。
- 事件守卫测试：可用按钮和链接触发记录；禁用控件及操作区空隙不触发。
- 退出登录测试：退出成功清空全部记录，失败时保留当前记录。
- 共享行测试：最近交互状态应用统一样式和非可见状态语义，普通行不受影响。
- 标准 `VTable` 页面组件测试：点击行操作会移动高亮；点击页面工具栏不触发。
- 视频列表测试：播放、采样、抽帧、标注和筛帧均可触发；选择框、启用开关和批量操作
  不触发；列表重新加载后仍按视频 ID 恢复。
- 数据集管理测试：Element Plus 主表正确应用单元格底纹；详情弹窗内明细表不应用。
- 训练任务详情测试：不同 GPU 分组共享一个最近模型，高亮可跨分组转移。
- 路由往返测试：列表组件卸载并重新挂载后仍恢复；重新加载整个前端应用后状态为空。
- 运行相关 Vitest、前端完整测试和生产构建。

## 非目标

- 不记录访问时间、操作类型、操作结果或历史轨迹。
- 不支持多行最近记录、跨浏览器同步或跨登录会话保留。
- 不自动跳转到下一条数据，也不调整列表顺序。
- 不把所有现有或未来表格默认纳入；新增页面必须显式选择作用域并接入。
- 不在本次工作中迁移视频台账或数据集管理表格到 `VTable`。
