# 项目背景与目标

状态：总体重构需求与技术基线已确认，首次初始化应用基础已实现。

## 背景

本项目源于一个供个人使用的单机数据集管理工具 `dataset-manager-1`。遗留工具已经形成视频数据集生产闭环，但前端界面朴素，后端和前端均高度集中，后台任务依赖单进程线程与内存队列，也没有用户、权限和租户边界，无法直接满足多人并发使用。

新项目不是在遗留代码上继续堆叠功能，而是提取其已验证的业务语义和核心算法，重新设计可维护、可测试、可恢复的前后端基础，再逐步扩展数据类型和标注能力。

## 目标用户

已确认的用户范围：

- 第一阶段：在共享 Linux 服务器或本地实例上管理视觉数据集的部门成员。
- 多用户：在同一部署中按私有项目协作的所有者、编辑者和只读成员。
- 后续阶段：需要人工标注、模型辅助标注和数据质量治理的算法与数据人员。

项目默认仅创建者可见，可邀请 owner、editor、viewer；系统管理员负责用户和注册审批，但多用户模式下不自动读取全部项目内容。

## 业务目标

### 第一阶段：视频主链路重构

- 保留项目注册、视频导入、下载、采样、抽帧、帧筛选、分组和数据集导出能力。
- 把单文件实现拆成职责清晰的模块，并建立统一 API 和版本化数据库迁移。
- 让耗时任务可持久化、可查询、可恢复，并在多进程部署下保持一致。
- 约束服务端文件访问范围，消除遗留实现中的任意路径访问和目录穿越风险。
- 用更高信息密度、低操作摩擦的 UI 改善日常工作效率；视觉方向参考 YouTrack 和 Ultralytics Platform，但不复制其品牌或具体界面。

### 系统基础：多用户与运行模式

- 默认多用户账号密码模式，同时支持单用户密码、Token 和受限无认证模式。
- 增加身份、会话、注册审批、项目成员、角色和资源权限模型。
- 隔离不同用户和项目的任务、数据与事件流。
- 为关键变更提供可追踪的操作者和审计信息。

### 后续阶段：数据类型与智能标注

- 在视频主链路稳定后，实现图片数据集导入、类别映射、标签过滤和相似图去重。
- 提供在线标注工作流。
- 支持读取模型并创建自动标注任务。

## 非目标与阶段边界

以下内容不进入第一批视频主链路实现：

- 直接合并 `feature/image-dataset-manger` 分支代码或迁移遗留数据。
- 在线标注器和模型推理服务。
- 未经确认的企业组织、计费、审批或复杂 ABAC 规则。
- 对遗留 API、数据库 schema 或目录布局的无条件二进制兼容。

如需迁移历史项目，应提供显式、可测试的导入或迁移工具，而不是继续在普通查询请求中隐式修改 schema。

## 已验证的遗留能力

遗留项目当前可证明具备：

- Vue 3 单页应用与 Flask API。
- SQLite 管理数据库和项目数据库。
- yt-dlp 远程视频下载以及本地文件导入。
- FFmpeg 采样抽帧和 SSE 进度。
- 帧启停位图、视频分组、YOLO 数据集导出。
- 一个未合并的图片数据集管理原型分支。

详细的遗留实现、状态机、接口、风险与证据保存在本地研究报告中，不在长期项目文档中重复维护。

## 成功标准

第一阶段至少满足：

- 核心视频工作流具有端到端自动化测试。
- 状态转移由单一业务模块控制，非法转移可被稳定拒绝。
- 下载、抽帧、分组和导出任务在服务重启后可恢复或明确失败并重试。
- 数据库迁移有版本、有测试，不在普通 GET 请求中执行。
- 文件只能在配置的存储根目录内访问，所有下载或预览接口使用安全路径解析。
- API 契约、前端客户端和接口文档保持同源或可自动校验。
- 源码、测试、容器与 CI 使用一致的运行时版本和依赖锁。

常规容量目标为在线数据集操作用户不超过 5、视频采样用户不超过 3、模型训练用户不超过 2。实际任务并发由全局和单用户资源限制控制，不等同于同时运行相同数量的 FFmpeg 或模型进程。

## 约束与原则

- `.ai-local/references/` 是只读参考材料，不作为新项目运行依赖。
- 新实现以清晰、可验证的最小架构开始，避免为未确认需求建立扩展框架。
- 数据库与文件系统的跨资源操作必须可检测、可重试或可补偿。
- 文档只描述已实现事实或明确标注的目标设计；实现状态变化时同步更新。
