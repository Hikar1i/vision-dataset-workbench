# UI/UX 设计系统

状态：已批准，所有前端 UI/UX 工作必须遵守。

本文件是 Vision Dataset Workbench 的 UI/UX 长期约束。页面级实现可以在不改变业务语义的前提下调整排版，但不得绕过本文规定的视觉令牌、页面结构、交互反馈、目标分辨率和评审门禁。

## 产品与视觉方向

- 产品定位：面向视觉数据生产、标注、筛帧、训练和模型管理的专业桌面工作台。
- 基础风格：`Soft UI Evolution` 与 `Drill-Down Analytics`，强调清晰层级、适度柔和和高密度可读性。
- 管理页面使用浅色工作区；标注、筛帧等专注工作区使用同一设计系统的深色变体。
- 禁止大面积渐变、玻璃拟态、AI 紫色、霓虹 HUD、无意义发光、漂浮装饰和过量圆角。
- 不改变现有主布局：左侧菜单、右侧功能区，以及标注和筛帧整页工具栏、工作区、轨道和属性面板布局。

## 目标分辨率

- 正式验收分辨率仅为 `1920×1080` 和 `2560×1440`。
- 不实施移动端和窄屏适配，不为 375px、768px 等断点增加抽屉、堆叠或降级布局。
- 右侧功能区使用流式网格；2560px 下扩展表格、画布和并排面板，不放大整套界面，也不限制为窄栏居中。
- 标注、筛帧的侧栏、工具栏和属性面板保持稳定宽度，中央画布吸收额外空间。

## 字体与字号

保持当前系统的字体性格，不引入网络字体依赖：

```css
--vdw-body: Inter, "Noto Sans CJK SC", system-ui, sans-serif;
--vdw-title: Bahnschrift, "Noto Sans CJK SC", sans-serif;
--vdw-mono: "Noto Sans Mono CJK SC", ui-monospace, monospace;
```

标准字号：

- 页面标题：24px。
- 区块标题：17px。
- 正文与主导航：15px。
- 按钮、表格副文本、表头、统计说明：14px。
- 状态标签、短 ID、时间戳、单位、画布覆盖信息：13px。
- **任何文字不得低于 13px**，包含第三方组件内部结构。下限由 `styles/base.css` 兜底而非依赖页面自觉：`<small>` 的浏览器默认 `0.8em` 与 `el-switch` 的 `inline-prompt` 都会跌破下限，已在基座里钉住。

Element Plus 使用基础 15px、小号 14px、超小号 13px；默认控件高度 38px。正文行高约 1.5，表格与控件不得依赖浏览器默认 `normal` 行高形成紧缩视觉。

## 页面骨架

```text
AppShell
├─ 左侧导航：256px，可收起至 72px
└─ 右侧功能区
   ├─ 顶栏：可点击面包屑 / 任务中心 / 用户菜单
   ├─ PageHeader
   │  ├─ [返回] eyebrow（22px 定高）：页面类型 / 对象 ID / 权限
   │  ├─        标题
   │  ├─        副信息（21px 定高）：统计或状态摘要
   │  └─ 末行（48px 定高）：子页签（左）───── 页面操作（右）
   └─ 页面主区域
```

- 面包屑除当前层级外必须是可访问的真实链接。
- **三段定高且始终渲染**，不用 `v-if` 省略空段。否则带权限标签的项目页会比列表页高、
  没有子页签的页面会比有页签的矮，标题与正文起点随页面漂移。
  验收标准：所有页面的 header 高度、标题顶边、正文起点三个数值必须完全相同。
- eyebrow 内的标签（权限等）高度必须小于 22px，否则会撑开该行。
- 页面操作与子页签同行右对齐，最多一个 `primary`。
- **只属于某个子页签的动作不得放进 header 操作区**：用户切换页签时它会凭空消失，
  该动作应下移到对应子页面的页内工具行。
- 统计信息只出现一次（header 副信息位），页内不得重复渲染同一数字。
- 登录、注册和初始化使用浅色令牌，保留独立流程布局。

共享组件保持最小化：使用一个 `PageHeader` 统一重复页面头部；不为单一页面创建抽象组件。`ProjectLayout` 和 `FocusLayout` 继续承担现有职责。

## 组件规则

### 按钮与图标

- 默认按钮高 38px、小号 30px、圆角 5px。
- 只有四种角色，全部由 `VButton` 提供，页面不得自写按钮样式：
  `primary` 实心近黑（每屏最多一个）、`default` 浅灰底中性次要动作、
  `quiet` 无边框行内操作、`danger` 危险操作。
  主按钮用近黑而非青绿：青色留给数据，否则表格里的"进行中"会和按钮混淆。
- 不存在"指引下一步"的按钮角色。实测用户读不出这层含义，只会觉得它和主按钮
  分不出主次；同一行里也不得把某个操作提升为更重的角色。
- hover 只改变颜色、边框和阴影，不产生位置变化；active 使用轻微内阴影或亮度变化。
- **禁用态靠对比度**：用 `--vdw-ink-disabled`（白底 2.45:1，对比可用态 6.14:1）
  并把图标透明度压到 0.55。不得用删除线——1px 浅灰线与可用态几乎分不出。
  行内 `quiet` / `danger` 禁用后不画底色和边框：禁用项绝不能比可用项更显眼。
  同时必须保留原生 `disabled`、`cursor: not-allowed` 与说明原因的 `title`。
- 普通操作图标统一使用 `@element-plus/icons-vue`。同一区域不得混用图标库。
- **列表行操作必须带图标**，且同一动作全系统使用同一图标。
- 不手绘菜单、返回、刷新、增删、展开收起等常见图标；领域专用标注几何图形可以保留 SVG。
- 图标按钮必须有 `aria-label` 或 `title`，并且**必须真的渲染出图标**：
  只给 `title` 而不给图标插槽会渲染成一个空方框（曾在 10 处出现）。
  用 `VButton` 的 `icon-only` + `label`，前者保证 38×38 方形尺寸，后者提供无障碍名称。

### 页签、卡片与表格

- 子页签使用浅灰蓝分段容器；当前项使用白色表面、青绿色文字和轻阴影。
- 卡片圆角 7px，控件圆角 5px，状态标签使用胶囊形。
- 状态标签与短标识必须为**内容宽度**（`width: fit-content` + `justify-self: start`）。
  作为表格 grid 子元素时默认会被拉伸到整列宽，短文本配长胶囊不可接受。
- 状态标签统一走 `VTag`，短标识走 `VChip`，**不得使用 `el-tag`**：它默认 12px、直角、无色点，
  与 `VTag` 观感不一致。状态 → 语气的映射只允许写在 `ui/status.ts`，页面不得自行三元判断，
  否则同一状态会在不同页面呈现不同颜色。
- 深色专注区（`.vdw-dark`）里，青色 `--vdw-focus-accent` 只作描边与文字色。
  它亮度高，做实心底色配白字实测仅 2.06:1；必须承载文字时配深字（8.1:1）。
- 阴影仅用于浮层、可交互卡片和 hover 反馈；普通数据表依赖边框和表面层级。
- **表头与行内元素一律左对齐**（含操作列），列间隔由 16px 列间距负责，
  不靠单元格内的对齐制造间隔。居中/右对齐会让每列视觉起点不同，扫读困难。
- **表头不得折行**：列不够宽时改表头文案或加宽该列。折行会把行高撑高一倍
  并让相邻列基线错开。
- 表单保存必须按后端实际结果播报：后端逐项校验、把非法项放进 `rejected` 而非抛错时，
  不得无条件提示成功。全部被拒要报错并说明原因，部分被拒要给出两个数量。
- 表头字号 14px、字重 500；数据行最小高度 64px，且行内必须有 12px 上下内边距。
  高密度台账若没有行内留白，用户扫读时无法分辨行边界——这是实测确认的问题，不得为了塞更多行而压缩。
- 可点击表格行或卡片必须显示指针、背景和边框反馈，不得通过位移表达 hover。

### 表单与状态

- 表单、弹窗、抽屉、空状态、错误状态和加载状态优先复用 Element Plus，并通过全局令牌统一。
- 输入框必须有可见标签；禁用、只读、错误和成功状态不得只靠颜色区分。
- 错误信息说明发生了什么以及用户如何修复，不使用模糊文案。

## 动效

- hover 与 press：120–180ms。
- 页签与面板切换：180–240ms，进入使用 ease-out，退出使用 ease-in。
- 侧栏和展开区：240–280ms，可组合轻微位移和透明度。
- 禁止弹跳、漂浮、数字滚动和整页入场动画。
- 必须遵守 `prefers-reduced-motion`；关闭动画后不得影响功能和状态可见性。

## UI/UX Review 门禁

所有涉及页面结构、样式、组件外观、图标、动效或交互反馈的任务必须设置以下标记：

```text
UI/UX REVIEW REQUIRED
```

满足以下条件后，独立 reviewer 才能将其改为：

```text
UI/UX REVIEW PASSED
```

评审要求：

1. reviewer 必须与主要实现者分离，可以是独立 subagent 或后续 agent。
2. reviewer 必须先阅读本文件，不得仅凭个人偏好评审。
3. reviewer 必须显式使用 Chrome 查看实际系统，不得只审查源码或测试快照。
4. 在 `1920×1080` 和 `2560×1440` 下核对代表页面，包含普通列表、详情、带子页签页面、弹窗或抽屉、标注工作台和筛帧工作台。
5. 核对字体、字号、溢出、对比度、图标、hover、active、focus、展开收起、加载、空状态、错误状态和 reduced-motion。
6. 记录发现的问题和复查结果。存在未解决的阻断问题时不得写 `UI/UX REVIEW PASSED`。

主要实现者也必须在开发过程中显式使用 Chrome 做中间核对；独立评审不能替代实现阶段的自检。
